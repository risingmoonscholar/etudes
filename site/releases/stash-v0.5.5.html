stash · v0.5.5

stash v0.5.5 — locked items and checked moves

Stash no longer calls a folder clear while a locked item is still in it.

  • Files and folders with the locked flag are left in place. A folder with a locked item in it is not called clear: stash moves the rest, says the folder is NOT clear, and exits 3 with status incomplete. A folder that holds only locked items moves nothing and reads refused with permission_denied. Every message says how to clear the flag.
  • stash select of only a locked item now reads refused with permission_denied; it still exits 3.
  • On macOS each move goes into the holding folder that passed the check: the folder is opened without following a link and its device and inode are checked on the open folder. A folder swapped for a link during the move is refused instead of followed. stash pop moves items back the same way.
  • On macOS each move also takes the item from the folder that was checked. A folder swapped during the move stops the stash with plan_stale and nothing more is moved out of it. The Finder tag check and the locked-flag check still read by path.
  • A move that failed after its copy to another disk landed no longer leaves that copy behind while saying nothing moved. If the copy cannot be removed, the message names it and gives the step; --json adds details.copy_left.
  • A stash kept longer than 30 days keeps its undo record for as long as it holds anything, so stash pop still finds it. Before, the next sweep run deleted it. A popped stash's record expires 30 days after the pop. A record that does not open with the current key is never removed by the tools, and stash status --all names it as unreadable.
  • stash status in a folder with nothing stashed points to a stash in another folder, and its steps now work when pasted. The path is quoted, so a name with a space, a quote or a control character stays one word. When that folder holds two or more stashes, it says how many and prints stash pop FOLDER --latest instead of a bare pop that refuses.
  • stash status no longer prints a stash pop step that cannot work. A holding folder with no undo record (made with --no-journal, or the record is gone) is named, with a note to move the items back by hand. A stashed folder that was moved or renamed is found by device and inode: status says where the stash was made and prints mv NEW OLD and stash pop --id ID.
  • Two stash pop of one stash at the same time no longer both move the same items back. The second says a stash or stash pop is running on this stash and waits. A pop that starts while the stash itself is still moving items waits the same way, because stash holds its undo record from its first recorded move. If the first restored everything, the second says "Nothing to restore. Another `stash pop` restored this stash." and exits 1 with nothing_to_do. If the first stopped part way, the second restores the rest. This needs advisory locks on the volume that holds the undo records.
  • stash status and stash pop no longer call a record damaged because a run is writing it. stash status of a stash that is still moving says a stash or stash pop is running on it now, with how many items are in its holding folder so far, and gives the step to see it again; stash status --id ID --json waits for that run. A pop that waited never restores a stash made after it started: it says so and restores nothing.
  • When a stash's holding folder is gone and files with its items' names, sizes and times are back in the folder, stash status says so and gives stash pop --id ID, which checks them against the record and says they are "already back in place". Files that only share the names are not taken for the items.
  • A stash FOLDER that loses a race with another run of the same folder now exits 2 with plan_stale and says "FOLDER changed just now, perhaps by another run. Nothing was moved. Run it again." Before, it exited 3 with missing_input and printed a --export-plan NEW_PLAN_FILE step that named a plan you never made.
  • When the newest live stashes have the same time, stash pop --latest moves nothing, exits 3 with journal_times_tied and prints stash pop --id ID for each one. stash pop FOLDER chooses by folder, so a tie no longer blocks it.
  • A duration you typed for stash --for is shown as you typed it in messages, without debug quotes and backslashes.
  • --progress-json now covers stash, stash select, stash pop and restore. They used to refuse the flag with exit 2.
  • An argument that is not valid UTF-8 is refused with exit 2 and invalid_arguments. It used to panic.

JSON: the result envelope stays at schema_version: 4. The stash capability declaration is version 15; it lists the refusal code journal_times_tied for stash pop.
