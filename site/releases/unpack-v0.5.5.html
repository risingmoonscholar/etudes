unpack v0.5.5 candidate — leftover cleanup and progress

A later extraction cleans up after a killed one, but only what it can prove is its own leftover.

  • A later extraction into the same destination removes a folder left by a killed extraction, and names it on stderr. It first checks the exact name, that the folder is a real directory you own, that its lock file names that very folder by device and inode, and that the lock is free. A running extraction holds the lock.
  • A symlink, a copy of a leftover, a folder from an older version and anything else unproved stay in place, and each is named with a step that works. A failed removal does not block the extraction. --json adds leftover_folders_removed and leftover_folders_kept under effects when not zero.
  • --progress-json now covers extraction and --list. Progress comes from the judged listing and the private staging folder, not from extractor output. Redirected runs of 100 or more members print milestones on stderr.
  • SECURITY.md now states that code running as you can forge the staging marker that this cleanup checks.
  • An argument that is not valid UTF-8 is refused with exit 2 and invalid_arguments. It used to panic.

JSON: the result envelope stays at schema_version: 4. The unpack capability declaration is version 8.
