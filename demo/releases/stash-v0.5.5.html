stash v0.5.5 candidate — locked items and checked moves

Stash no longer calls a folder clear while a locked item is still in it.

  • Files and folders with the locked flag are left in place. A folder with a locked item in it is not called clear: stash moves the rest, says the folder is NOT clear, and exits 3 with status incomplete. A folder that holds only locked items moves nothing and reads refused with permission_denied. Every message says how to clear the flag.
  • stash select of only a locked item now reads refused with permission_denied; it still exits 3.
  • On macOS each move goes into the holding folder that passed the check: the folder is opened without following a link and its device and inode are checked on the open folder. A folder swapped for a link during the move is refused instead of followed. stash pop moves items back the same way.
  • --progress-json now covers stash, stash select, stash pop and restore. They used to refuse the flag with exit 2.
  • An argument that is not valid UTF-8 is refused with exit 2 and invalid_arguments. It used to panic.

JSON: the result envelope stays at schema_version: 4. The stash capability declaration is version 13.
