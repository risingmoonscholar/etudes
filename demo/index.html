etudes

Three command-line tools for macOS. Tidy a folder, put it aside for later, or unpack an archive.

An étude is a short piece written to master one technique, and in the right hands also worth performing. These are built the same way: each removes one recurring friction, each is small enough to read in an afternoon, and each can prove its own claims rather than asking you to trust them.

Every terminal block below is recorded output from the real binaries, run against a synthetic fixture. Nothing is executing in your browser, and nothing is hand-written. How that is guaranteed.

Provenance

The demos are captured, never authored. scripts/capture-demos.sh builds the binaries out of the tree, generates a synthetic fixture with mkfx, runs each command, and writes the raw stdout to demo/transcripts.json together with the commit it was built from. Regenerate it and diff: a transcript that no longer matches the tool is a build failure, not a stale document.

The fixture is generated, not collected. Files with alarming names like SSN_card_scan.jpg are decoys whose contents read SYNTHETIC TEST FIXTURE - NOT REAL DATA. The tree is built in a temporary directory and deleted when the script exits. No real file is read during development, testing, or capture.

One edit is made to the captured text: the temporary directory is rendered as ~/Desktop, because its real name is machine-specific noise. That rule is declared in the artifact, and nothing else is touched.

Check the claims yourself

The second is macOS-only. It uses sandbox-exec, and elsewhere exits 2 saying the claim cannot be made on this host. A witness that quietly passes where it cannot observe anything is worse than no witness.

Witness

A test that passes is not the same as a test that checked something, and nothing in a green summary distinguishes them. Witness is the name for the checks in this repo that can testify: each one can demonstrate it is able to observe the failure it claims to rule out.

Night Watch

Night Watch is the agent that runs these against this repo and writes up what it finds. I run it by hand, and it drafts rather than posts. The open issues are its output. Each carries its own attribution, and the wording in them is the agent's rather than mine.

bash stress/run.sh 38 scenarios · pass / FAIL / unproven, counted separately exit 0 pass · 1 fail · 2 nothing proven

The failures are real and left open on purpose. A repository that argues for honest reporting and hides its own defect list would be making the opposite argument. Read them. They include a data-loss bug introduced by one of my own fixes.

This is what I have an agent doing on a small project. If it is missing something obvious, I would rather hear it than not.
